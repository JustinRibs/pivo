    Section order

    Drag to reorder how sections appear in the newsletter. Disabled or empty sections are simply skipped.

      Playful sections

      Playful, data-driven sections that give the newsletter personality. Each one quietly hides itself when there's no data to show.

      Sixteen awards are computed from your watch history each period — completion habits, weekend patterns, longest single sitting, oldest thing anyone dug up, and so on — but only the ones with a real winner qualify, and only this many are shown. Without AI curation you get the strongest qualifiers in a fixed priority order.

      The awards read your Tautulli watch history over the stats window set on the Content page. Seasonal theming temporarily overrides your accent color around Halloween, the winter holidays, Valentine's, and a few others.

      Uptime badge

      Reads the aggregate uptime from a public status page on your uptime monitor (Uptime Kuma). The slug is the part of the status-page URL after /status/. Recipients just see a friendly percentage — no jargon.

      AI-written copy

      Hands the already-computed award facts to a language model and lets it rephrase them with some personality. The model never sees your raw watch history and never produces a number — if it fails, times out, or returns junk, the newsletter silently falls back to the standard wording.

      Hands the model the whole bench of qualifying awards and lets it choose which ones run this week, in what order, and what to call them — inventing the category name and picking the emoji. The winner and the number are still computed in code and cannot be changed by the model, so a renamed award always belongs to the right person. Expect the section to look different week to week; that's the point.

      The subject is otherwise a fixed template and the inbox preview line never changes at all, so every edition looks identical in a crowded inbox — letting the model name what's actually in this one is the difference between a mail that gets opened and one that doesn't. If a call fails or a cap blocks it, your Newsletter subject template from the Schedule page is used instead.

      Blurb rewriting compresses the synopsis Plex already stores into one line that fits without being chopped mid-word. The model is given that synopsis and told to work only from it — it is never asked what a title is about, which is where it would start inventing plot. Needs Show summaries on in the Content page, applies to movies and albums (TV episodes carry no synopsis), and is the one option that noticeably grows the prompt: up to 12 items, each synopsis trimmed to 300 characters before it is sent.

      Model & provider

      Reasoning models charge their thinking to the same output budget as the answer, so a model left on its default effort can spend the entire max output tokens thinking and return nothing. Writing one-line captions from facts that are already correct needs no reasoning at all, so none is both cheaper and better here. Endpoints that don't understand the parameter have it dropped automatically.

      OpenAI-compatible covers OpenAI, OpenRouter, Groq, Together, DeepSeek, Mistral, LM Studio, llama.cpp and vLLM — point the base URL at any of them. Ollama uses its native API so it can pass keep_alive; 0s unloads the model from VRAM the moment the newsletter is composed, which matters if the same GPU also handles Plex transcodes. Leave the API key blank for local backends.

      Spend limits

      Caps are checked before each request and measured over rolling windows, so they can't be reset by waiting for midnight. Hitting one is not an error — the newsletter just falls back to the standard wording, same as a timeout. Set either to 0 to remove that limit. Local Ollama models cost nothing to run; the counters still tick so you can spot a runaway prompt.

      The preview recomposes the whole newsletter on every page load. Response reuse is what stops a tuning session from billing once per refresh — an identical provider, model, prompt and output ceiling is served from cache. Changing the tone direction changes the prompt, so you still see the effect of an edit immediately.

      Connection

      The container needs to reach Tautulli over the network. Posters are fetched server-side and embedded in the email, so recipients don't need direct access.

      Coming Soon section

      Pull a Coming Soon section into the newsletter — upcoming movie releases from Radarr and upcoming episode air dates from Sonarr, over the next days. Cover art is shown alongside each item. Leave either one disabled if you only run one of them.

      The master toggle hides the section entirely without losing your Radarr / Sonarr connection details below. With replace on, weeks with upcoming content will swap out the "what got added" sections — and weeks without will quietly fall back to Recently Added.

      Radarr

      Sonarr

      Posters are pulled from TMDB / TVDB (publicly hosted), so they embed directly without going through your Radarr/Sonarr instance.

      Request button

      Add a "Request a movie or show" button near the bottom of the newsletter, linking to your Overseerr / Jellyseerr instance (or any URL). Lets recipients ask for content right from the email.

      Cloudinary

      By default, posters are attached to each email as inline (CID) images. Most clients render them inline, but Apple Mail, iOS Mail, and Outlook also list ~30 of them as attachments. Hosting posters on Cloudinary (free tier is plenty) keeps the email lightweight — each poster is uploaded once, cached, and embedded as a regular <img src="https://…">.

      Find these in Cloudinary under Settings → API Keys. Posters are deduplicated by Plex rating_key + thumb version, so each poster is only uploaded once.

      SMTP server

      Pivo works with any SMTP provider — Postmark, Brevo, Mailgun, SendGrid, Amazon SES, or your own self-hosted relay. Grab the host + port + credentials from your provider's dashboard.

      For best deliverability, set up SPF, DKIM, and DMARC DNS records on your sending domain in your SMTP provider's dashboard. Without these, Gmail and Yahoo will route your emails to spam.

      Public URL (for unsubscribe links)

      Used to build per-recipient unsubscribe links and the List-Unsubscribe header (one-click compliance for Gmail / Yahoo). Leave blank to omit unsubscribe links — fine for a tiny private list, not recommended for anything bigger. No trailing slash, e.g. https://newsletter.yourdomain.com.

      Add a recipient

      Pulls everyone with shared access who has an email on file in Tautulli. New imports start inactive so you can review them before they receive anything.

      Plex users without an email — add manually

      These users have access to your server but Tautulli doesn't have their email. Names are pre-filled — just enter their address.
